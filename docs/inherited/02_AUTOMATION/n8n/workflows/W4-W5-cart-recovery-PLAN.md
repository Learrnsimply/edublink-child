## 1) الجروب المستهدف بالظبط (مهم — منزعّجش اللي دفع)

WooCommerce status بيحدّد كل حاجة (من `order_lookup.md` §5.1):

| status | معناه | نعمل إيه؟ |
|---|---|---|
| `pending` | **الدفع ماكملش** | ✅ **ده هدف W4** — نبعتله تذكير |
| `on-hold` | دفع محفظة مستني تأكيد أحمد | ❌ متلمسوش — هو دفع فعلاً |
| `processing` / `completed` | مدفوع | ❌ متلمسوش |
| `cancelled` | اتلغى بعد 24 ساعة | 🎯 **ده هدف W5** (الباكلوج التاريخي) |
| `failed` | فشل تقني | ⚠️ نعامله زي pending (تذكير) — بس بحذر |

**النافذة الحية:** بعد ما طوّلنا `hold_stock_minutes` لـ 1440، الأوردر بيفضل `pending` لمدة **24 ساعة** قبل ما يتلغى. دي نافذتنا.

**حقيقة من الـ deep dive:** الدافع الحقيقي بيدفع في **median 3.67 دقيقة**. عشان كده **منبعتش تذكير قبل 45 دقيقة** — عشان منزعّجش اللي هيدفع لوحده. 41% بيرجعوا يكمّلوا لوحدهم.

## 2) المعمارية (Architecture)

### القرار: poll مجدول (مش webhook + Wait طويل)

```
┌─────────────────────────────────────────────────────────────┐
│  W4 — Cart Recovery (n8n scheduled, every 20 min, 9am–9pm)   │
│                                                              │
│  Schedule Trigger ──> WC: GET pending orders (آخر 24 ساعة)    │
│       │                    (read-only key الموجود)            │
│       ▼                                                       │
│  لكل أوردر: شوف الـ idempotency store (n8n Data Table)        │
│       │                                                       │
│       ├─ عمر 45د–2س + مفيش R1 اتبعت ──> ابعت R1 ──> سجّل       │
│       │                                                       │
│       ├─ عمر 18–22س + R1 اتبعت + R2 لأ ──> ابعت R2 ──> سجّل   │
│       │                                                       │
│       └─ غير كده ──> تجاهل                                     │
│                                                              │
│  الإرسال: n8n "Send Email" node عبر Brevo SMTP (creds موجودة)│
│  الـ STOP: الـ poll نفسه بيجيب pending بس — اللي دفع/اتلغى    │
│            بيختفي من القايمة تلقائياً (مفيش إرسال غلط).        │
└─────────────────────────────────────────────────────────────┘
```

**ليه poll مش webhook+Wait؟**
- الـ Wait لـ 18 ساعة = execution معلّق طويل = هشّ في queue mode.
- الـ poll بيقرا حالة الأوردر **الحية** كل مرة → لو العميل دفع، الأوردر مبقاش `pending` → **اختفى من القايمة → مفيش إرسال**. ده الـ stop condition الطبيعي، أأمن من أي flag.

**ليه Send Email عبر Brevo SMTP (مش Mautic email)؟**
- كل أوردر محتاج **لينك دفع فريد** (order-pay URL — تحت §3). الـ SMTP node بيبني HTML ديناميكي لكل أوردر بسهولة.
- بيعيد استخدام **Brevo SMTP creds الموجودة** — مفيش credential جديد.
- الرسائل دي **transactional-class** (عن أوردر العميل عمله بنفسه) → مناسب للـ SMTP المباشر.
- التتبّع: UTM على اللينك → GA4 بيشوف التحويل + Brevo dashboard بيشوف الـ delivery.

> 🔸 **بديل** (لو Omar يفضّله): الإرسال عبر Mautic API بدل SMTP المباشر — يدّي stats جوه Mautic بس بيعقّد حقن اللينك الفريد. **توصيتي: SMTP المباشر.**

### الـ idempotency store

عشان منبعتش R1 مرتين أو R2 قبل R1:

| الخيار | المميزات | العيوب | التوصية |
|---|---|---|---|
| **n8n Data Table** (native) | جوه n8n، صفر setup خارجي، يتدار بنفس الأداة | feature أحدث | ✅ **مقترح** |
| Postgres table (`recovery.log`) | متين، query قوي | يحتاج migration | بديل |
| WC order meta | مفيش store منفصل | يحتاج **write key** لـ WC (مش عايزينه) | ❌ |

> الجدول: `recovery_log(order_id PK, r1_sent_at, r2_sent_at, customer_email)`.

## 3) لينك استكمال الدفع (الـ magic link)

WooCommerce بيدّي لينك يكمّل بيه العميل دفع **نفس الأوردر الـ pending**:

```
https://learrnsimply.com/checkout/order-pay/{order_id}/?pay_for_order=true&key={order_key}
  + &utm_source=brevo&utm_medium=email&utm_campaign=cart_recovery_r1
```

- `order_id` + `order_key` بييجوا من WC REST (نضيفهم في `_fields`).
- ده بيرجّع العميل لصفحة الدفع بنفس الأوردر — **مش سلة جديدة**، استكمال مباشر.
- ⚠️ ده شغّال للـ `pending` بس. الـ `cancelled` (الباكلوج) لينكه ميت → W5 بيوجّه لصفحة المنتج بدلاً منه.

## 4) محتوى الإيميلات (RTL عربي، صوت Learn Simply)

> بلا خصم. تذكير + تبسيط الدفع + بديل المحفظة. نبنيهم بـ `_tools/build_campaign_emails.py` (UTM أوتوماتيك) + نفس template إيميل 1.

### 📧 R1 — تذكير أول (بعد ~1 ساعة)
- **الموضوع:** «أوردرك لسه مستنيك 🎓 — كمّل في دقيقة»
- **الجسم:** ودود ومباشر. "بدأت تشترك في [اسم الكورس] وما كمّلتش — اللينك جاهز تكمّل منه دلوقتي." + زرار **استكمل الدفع** (الـ magic link) + سطر: "بتفضّل تدفع بفودافون كاش أو إنستاباي؟ ابعتلنا واتساب على `01030127228` ونظبّطك."
- **النبرة:** مساعدة مش إلحاح. سطر واحد عن خيار المحفظة (يحل احتكاك الكارت).

### 📧 R2 — آخر تذكير (بعد ~18–20 ساعة، قبل ما يتلغي)
- **الموضوع:** «أوردرك هيتقفل قريب — تحب نكمّله؟»
- **الجسم:** إلحاح **صادق** (الأوردر فعلاً بيتلغي عند 24 ساعة، مش ددلاين وهمي). نفس الزرار + خيار المحفظة. "لو فيه أي حاجة واقفاك في الدفع، رد على الإيميل ده وهنحلّها."

### 📧 W5-blast — win-back تاريخي (مرة واحدة، للـ313)
- **الموضوع:** «لسه عايز تتعلّم [الكورس]؟ خليها تتم النهاردة»
- **الجسم:** مختلف — دول أوردرات قديمة ملغية، لينك الدفع ميت. نوجّه لـ **صفحة المنتج** اللي حاولوا يشتروه (من line_items) + خيار المحفظة بارز + سطر إنساني "حاولت قبل كده وما تمّتش — احنا هنا لو محتاج مساعدة."
- **شخصنة:** كل عميل + الكورس اللي حاوله (أحدث محاولة).

## 5) خطة البناء (مرحلتين)

### المرحلة A — W4 (الـ flow الجاري) — نبنيها ونختبرها الأول
1. **إيميلات R1 + R2** — نبنيهم في الأداة، preview، نراجعهم سوا.
2. **n8n Data Table** `recovery_log` — إنشاء.
3. **W4 workflow** عبر n8n-MCP: Schedule → WC pending query → loop + decision (عمر الأوردر × stage) → Send Email (Brevo SMTP) → log. + ربطه بـ W3d error handler (Telegram).
4. **اختبار:** أعمل أوردر pending تجريبي → أتأكد R1 بيتبعت بعد النافذة → **أدفعه → أتأكد R2 ماتبعتش** (الـ stop) → أتأكد مفيش إرسال مكرر (idempotency) → أتأكد UTM على اللينك + اللينك بيفتح صفحة الدفع الصح.
5. **تفعيل** بمعدل آمن (poll كل 20 دقيقة، 9ص–9م القاهرة).

### المرحلة B — W5 (الـ blast التاريخي) — بعد ما A تثبت
6. **استخراج الـ313** من WC: أوردرات `cancelled` بكارت، dedup بالعميل، اللي **ماكمّلوش أبداً** (مفيش أوردر مدفوع لاحق لنفس الإيميل). + الكورس اللي حاولوه.
7. **إيميل W5-blast** + preview.
8. **الإرسال:** ⚠️ Brevo free = **300/يوم**، والـ warmup throttle = **200/يوم**. الـ313 → **يتقسموا على يومين** (مثلاً 200 + 113). أرشّح الإرسال عبر **Mautic segment + campaign** (unsubscribe + throttle + امتثال) مش SMTP خام — لأنها marketing-class لناس قديمة، والـ spam complaints تضرّ سمعة الدومين اللي حملة الـ13K معتمدة عليها.

> 🔸 **قرار فرعي للـ blast:** Mautic (امتثال + throttle، أنضف) **ضد** n8n+Brevo SMTP (أبسط، بس بلا unsubscribe سليم). **توصيتي: Mautic للـ blast، SMTP للـ flow الجاري.**
