# تشريح قمع الشرا

> ٣ سبتمبر ٢٠٢٦. مشيت رحلة الشرا كزائر جديد بجلسة نظيفة من `/courses/dart/`.
> نسخة مقروءة منشورة كـ Artifact.

## القمع — آخر ٧ أيام (GA4)

```
149  add_to_cart
 95  begin_checkout     −36%
  8  purchase           −92%   ← أكبر فقد
```

وعلى ٢٨ يوم: **657 إضافة للسلة → 36 بيعة = 94.5% بيسيبوا**.

## رحلة الزائر الجديد — كل خطوة فيها احتكاك

1. **صفحة الكورس** — مقنعة. ٦٠٠ ج بدل ١٢٠٠، عرض محدود، زرار واضح
2. **«اشتري الآن» → `/dashboard/?redirect_to=/checkout/`** — مش صفحة دفع، **صفحة تسجيل دخول**،
   والرابط اسمه dashboard فبيحس إنه دخل مكان إداري
3. **«أهلاً بك مرة أخرى!»** — لزائر أول مرة. والنموذج الافتراضي «تسجيل دخول» وهو مامعهوش حساب
4. **نموذج التسجيل: ٦ حقول إلزامية** — الاسم الأول · الاسم الأخير · **اسم المستخدم** ·
   الإيميل · كلمة المرور · **تأكيد كلمة المرور**
5. **صفر ذكر للكورس أو السعر** في الصفحتين. وعنوان الصفحة `signup` بالإنجليزي
6. لو كمّل → الشيك أوت → checkbox تعهد إجباري → Kashier

**السلة سليمة** — الكورس بيفضل فيها طول الرحلة. المشكلة في الحاجز مش في فقد الطلب.

## السبب الجذري — سلسلة في الكود

```
strip_checkout_fields   →  شال كل حقول الفوترة ما عدا billing_email
fill_order_from_account →  فبقى بيجيب الاسم من الحساب
require_login           →  وبالتالي الزائر لازم يكون عنده حساب
```

التعليق في `functions.php` بيقولها صريح: "Guests cannot fill the hidden billing form,
so checkout requires an account".

**والحل جوه المشكلة:** `billing_email` **لسه موجود**. فالزائر يقدر يدفع كضيف،
والحساب يتعمل تلقائيًا بعد الشرا وتتبعتله بياناته.
